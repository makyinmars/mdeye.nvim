1. INTRODUCTION					*mdeye-introduction*

mdeye.nvim opens a Markdown buffer as a separate, read-only document view:
a generated preview buffer with semantically reflowed paragraphs, a centered
maximum-width reading column, source markers removed, and semantic
highlights. It is a document viewer, not source decoration, and it never
opens a browser or webview.

The source buffer is authoritative and is never modified. Unsaved edits
update an open preview live (debounced). Every rendered block keeps its
absolute source span, so you can always jump back to the exact source
location.

==============================================================================
2. REQUIREMENTS					*mdeye-requirements*

- Neovim 0.11 or newer.
- The `markdown` and `markdown_inline` Tree-sitter parsers (bundled with
  Neovim).

Verify with: >
    :checkhealth mdeye
<
==============================================================================
3. COMMANDS						*mdeye-commands* *:MDEye*

:MDEye			Toggle a preview in the current window.

:MDEye current		Open or focus the preview in the current window. The
			preview replaces the source in the window; `q`
			restores the source buffer, cursor, and view exactly.
			Requires 'hidden' when the source has unsaved
			changes; otherwise opening fails cleanly and split
			mode remains available.

:MDEye split		Open or focus a synchronized preview in a right
			split. Moving the source cursor scrolls the preview
			to the corresponding rendered block. The split is an
			ordinary resizable Neovim window.

:MDEye tab		Open or focus the preview in a new tab page.

:MDEye close		Close the preview and restore the source view when
			appropriate. Works from the preview or the source.

:MDEye copy-code	Copy the fenced block under the preview or source
			cursor. The unnamed register is always set; the `+`
			register is also set when clipboard support is present.

Opening the same source again focuses its existing preview instead of
creating a duplicate session. Non-Markdown buffers are rejected with one
notification.

==============================================================================
4. PREVIEW MAPPINGS					*mdeye-mappings*

Buffer-local mappings inside the preview:

q			Close the preview and restore the source view.

<CR>			If the cursor is on a link, open it. Otherwise jump
			to the source location of the block under the
			cursor, adding one |jumplist| entry.

gx			Open the link or in-document anchor under the cursor.

]] / [[		Move to the next / previous heading.

gO			Select a heading from the document outline.

yc			Copy the fenced code block under the cursor.
za / zo / zc            Toggle/open/close a heading or code fold.
zR / zM                 Open/close all preview folds.
zA / zO / zC            Recursive native fold operations.

In split mode, use `10<C-W>>` to grow the focused preview by 10 columns and
`10<C-W><` to shrink it. You can also drag the split separator when 'mouse'
is enabled (for example, `:set mouse=a`). The document reflows after each
resize while preserving the reading position. Set `max_width = false` (see
|mdeye-configuration|) if the reading column should keep growing with the
window instead of stopping at the default 88 cells.

mdeye installs no global keymaps. Suggested mapping: >
    vim.keymap.set("n", "<leader>me", "<Cmd>MDEye<CR>", { desc = "Markdown eye" })
<

5. LUA INTERFACE					*mdeye-lua*

setup({opts})					*mdeye.setup()*
	Apply configuration (see |mdeye-configuration|). Optional unless you
	change defaults.

open({opts})					*mdeye.open()*
	Open or focus a preview for the current Markdown buffer.
	{opts} is an optional table: >
	    require("mdeye").open({ mode = "current" })  -- "split" | "tab"
<
close()						*mdeye.close()*
	Close the preview related to the current buffer (source or preview).

toggle({opts})					*mdeye.toggle()*
	Close an open preview for the current buffer, or open one with the
	given mode.

copy_code()					*mdeye.copy_code()*
	Copy the fenced code block under the current preview or source cursor.

==============================================================================
6. CONFIGURATION				*mdeye-configuration*

Defaults: >
    require("mdeye").setup({
      open = "current",   -- default placement: "current" | "split" | "tab"
      max_width = 88,     -- maximum reading width; false follows the window
      min_margin = 3,     -- minimum margin on each side
      debounce_ms = 120,  -- live-update debounce in milliseconds
      mermaid = { enabled = true, layout = "graph" }, -- or "connections"
      images = {
        enabled = false,       -- opt in after configuring image.nvim
        max_width = 60,        -- display cells
        max_height = 16,       -- buffer rows
        max_file_size = 10485760,
        max_images = 32,
      },
      code = {
        wrap = false,     -- false: scroll; true: display-cell wrapping
      },
    })
<
The content width is `min(max_width, available_width - 2 * min_margin)`,
centered with symmetric margins. When `max_width` is false, the available
window width is used instead of a maximum. Renderer internals are deliberately
not configurable; highlight groups are the customization seam.

7. HIGHLIGHTS					*mdeye-highlights*

All groups use `:highlight default link` semantics, linking to Tree-sitter
markup groups or standard groups that exist in the active colorscheme. No
colors are hard-coded, and explicit user highlights are never overwritten.

  MDEyeText		Body text.
  MDEyeMuted		De-emphasized text (e.g. code-block language tag).
  MDEyeHeading1..6	Heading levels.
  MDEyeHeadingRule	Divider line under H1/H2 headings; thematic breaks.
  MDEyeEmphasis		Italic emphasis.
  MDEyeStrong		Strong (bold) text.
  MDEyeStrike		Strikethrough text.
  MDEyeCode		Inline code.
  MDEyeCodeBlock	Fenced code block background.
  MDEyeDiagram		Native Mermaid connection text.
  MDEyeLink		Link labels.
  MDEyeFootnote		Footnote references and definition markers.
  MDEyeQuote		Block-quote text and gutter.
  MDEyeAlertNote	Note alert title and gutter.
  MDEyeAlertTip		Tip alert title and gutter.
  MDEyeAlertImportant	Important alert title and gutter.
  MDEyeAlertWarning	Warning alert title and gutter.
  MDEyeAlertCaution	Caution alert title and gutter.
  MDEyeListMarker	List bullets and ordered markers.
  MDEyeTableBorder	Table borders.
  MDEyeTaskChecked	Completed task glyph.
  MDEyeTaskUnchecked	Open task glyph.

8. BEHAVIOR						*mdeye-behavior*

Preview isolation~
The preview buffer is named `mdeye://<path>` and uses `filetype=mdeye`,
'buftype' `nofile`, 'bufhidden' `wipe`, no 'swapfile', and 'undolevels' -1.
Markdown linters, LSP servers, diagnostics, and formatting autocmds never
attach to it. The preview window disables 'number', 'relativenumber',
'signcolumn', 'foldcolumn', 'cursorline', 'colorcolumn', 'list', 'spell',
and 'wrap' (mdeye generates real wrapped lines).

Live updates~
Source edits (including unsaved ones) schedule a debounced full re-render.
Resizing the owner window reflows the document and restores the block that
was at the top of the view, so reading position is preserved.

Links and navigation~
Link labels are visible; destinations are hidden but retained. Relative
links resolve against the source file's directory at interaction time,
never against Neovim's current working directory. Heading anchors work in
the current preview and linked Markdown files. Absolute http(s) and mailto
links also carry extmark `url` metadata (OSC 8) where supported.

The `]]` and `[[` mappings move between headings; `gO` opens a selectable,
indented heading outline. Source-to-preview synchronization continues to
track the same semantic heading block in split mode.

Quotes and alerts~
Block quotes use a consistent gutter and retain nested Markdown structure.
GitHub-style `[!NOTE]`, `[!TIP]`, `[!IMPORTANT]`, `[!WARNING]`, and
`[!CAUTION]` markers at the start of a quote render as semantic alert titles.
Their title and gutter link to diagnostic highlight groups; nested prose,
lists, links, and code continue through the ordinary Markdown layout path.

Mermaid fences                                         *mdeye-mermaid*
Fences labeled `mermaid` render native ASCII diagrams. The default graph view
draws shared nodes once with orthogonal edge lanes. Numbered source ports match
an edge legend; x marks a crossing, not a junction. LR/RL graphs use horizontal
placement when they fit, otherwise vertical placement. TD/TB/BT stack nodes.
Ordering follows declarations and direction, not Mermaid's browser algorithm.

Supported flowcharts: `flowchart`/`graph`, LR/RL/TD/TB/BT, ASCII letter/underscore
IDs followed by letters/digits/underscores, plain nodes, [rectangle], (rounded),
([stadium]), ((circle)), [[subroutine]], {decision}, -->/---/-.->/==> edges,
chains, -->|label| and -- label --> edges, semicolon-separated statements,
%% comments, single-line quoted labels, and later node-label updates.
Shapes are approximate. Nested `subgraph id[Title]` / `end` containers are
supported to depth eight. Group-level links and local direction overrides
retain source instead of discarding grouping.

Set `mermaid.layout = "connections"` for the pair-per-edge view. Ungrouped
graphs use that view automatically if shared routing cannot fit. Subgraphs
that cannot fit retain their source.

Sequences: `sequenceDiagram`, participant/actor declarations, as aliases,
autonumber, ->>/-->>/->/-->/--x/-x/--)/-) messages, self-calls, activate and
deactivate, and +/- message activation suffixes. # marks an active lifeline.
Arrow styles are approximated with ASCII. Notes support over, left of, and
right of. Regions support loop, alt/else, opt, and par/and, closed with end.
Use one sequence statement per line. Example: >

    ```mermaid
    sequenceDiagram
    participant Reader
    participant Plugin
    Reader->>Plugin: Open Markdown
    Plugin-->>Reader: Render document
    ```
<
Unsupported types, styling, directives, click actions, HTML/entities, Markdown
labels, and incomplete input retain the whole source with a fallback reason.
Limits: 100 nodes, 200 edges/events, 20 sequence participants, 500 lines, 64 KiB.
A pane too narrow for a sequence also shows source. No external runtime is
needed for native diagrams.

Set `mermaid.enabled = false` to always display source. `yc` and |:MDEye|
copy-code copy original fence content; <CR> jumps to its source. Customize
the MDEyeDiagram highlight group with :highlight.

Reading position and folding                           *mdeye-folds*
Heading sections and fenced code use native manual folds, initially open.
za/zo/zc and their recursive variants work in the preview; zR/zM open/close
all folds. Choices for retained source blocks survive live updates and resize,
including closed children inside a closed parent. Heading/anchor navigation
opens enclosing folds. Closing the preview discards its fold choices.

Reading positions track source edits and the text passage within a block.
Diagram rows carry node/event identities to preserve context through reflow.
Unchanged line and highlight ranges are retained on updates. Parsing and
layout still process the complete document.

Local images                                           *mdeye-images*
Configure image.nvim and its backend/processor independently, then enable: >

    require("mdeye").setup({ images = { enabled = true } })
<
Standalone image paragraphs reserve real buffer rows below linked alt text.
Relative files resolve against the source file directory; unnamed buffers use
the working directory. Quotes/lists can contain image paragraphs. Remote URLs
and images within prose remain linked alt text. No images are downloaded.

The adapter caches handles, constrains file size and dimensions, refreshes on
scroll/resize/folding, and clears images when removed or when the preview
closes. Missing files or backend failures retain alt text. Reservations use
a conventional 1:2 cell aspect estimate; the backend fits within the bounds.
The adapter adds no virtual padding. Other image plugins are not integrated.
:checkhealth mdeye reports availability and active image failures. The image
library is not loaded by default.

Code and footnotes~
Fenced code uses the Tree-sitter parser and highlight query matching its
language label. Common short labels such as `js`, `ts`, `py`, and `sh` are
normalized. If no parser or query exists, the exact code remains visible as
plain text. Language labels remain visible; over-wide lines scroll
horizontally by default or wrap when `code.wrap` is true. |:MDEye|
`copy-code` / `yc` copies the original, unwrapped content.

GFM-style `[^label]` references render as numbered links to cleanly rendered
definitions. Standard indented continuation blocks retain Markdown styling,
lists, and fenced code. An unresolved reference stays visible as `[^label]`.

Cleanup~
Closing a preview removes its buffer, window (split/tab), autocmds,
mappings, and timers. Wiping either the source or the preview — including a
preview wiped by an ordinary buffer switch, since 'bufhidden' is `wipe` —
terminates the session safely. Repeated open/close cycles leak nothing.

|:checkhealth| reports every active preview's placement and verifies that its
source buffer, preview buffer, owner window, and initial render remain valid.

==============================================================================
9. LIMITATIONS					*mdeye-limitations*

Neovim renders on a character-cell grid. mdeye reproduces document structure
and reading layout, not typography. It cannot provide proportional fonts,
per-heading font sizes, pixel-level spacing, or browser-quality tables.
Bold and italic rendering depends on the terminal and font. Local image
rendering is optional and depends on image.nvim and a compatible backend.
Raw HTML renders as readable plain text and is never executed. Footnote
continuation paragraphs must use standard four-space indentation.
